# Grader Rubric — QA-гейт драфту (грейдер, обіцяний у README 06-write)

Рубрика, якою **сліпий суддя** оцінює publish-ready драфт LinkedIn-поста ПЕРЕД показом
користувачу. Мета — прибрати «письменник ставить оцінку сам собі»: свіжий виклик моделі
грейдить драфт по цій рубриці, знаючи ТІЛЬКИ текст + тип поста + список «ЩО НІКОЛИ НЕ ПИШЕМО»,
без бекстори (чому обрали ідею, який outlier-референс, історія драфтів). Потім loop поки не візьме гейт.

Заземлено на `methodology.md`: §2.1 (хук > ідея), §2.3 (формула хука), §3.1–3.7 (структура),
§3.5 (форматування), §5 (viral levers), §6.3 (фідбек = залучення І потік лідів). Не generic-чекліст —
ваги калібруються з даних автора (див. «Калібрування»).

## Структурний передгейт (детермінований, до сліпого судді)

Шість конструкцій читаються як згенеровані навіть тоді, коли лексика чиста: забороненого
слова нема, тире нема, а текст усе одно ШІ-шний. Суддя, який оцінює «голос», їх зазвичай
пропускає. Тому вони знімаються ДО того, як спавнити суддю.

| Конструкція | Як виглядає |
|---|---|
| Myth flip | «Більшість команд думають, що онбординг це чекліст. Насправді це звичка.» |
| Тріада | «Ті самі стендапи. Ті самі тікети. Ті самі затримки.» |
| Дзеркальна пара | «Усі автоматизують перший лист. Ніхто не автоматизує фолоуап.» |
| Reversal | «Це не стратегія. Це вгадування.» |
| Upsell через кому | «Це не просто нотатник, це другий мозок.» |
| Порожній розгін | перший рядок без жодної цифри, назви чи дії |

Плюс два, які видно без читання: **будь-яке довге тире** (найчіткіший слід) і **рівний ритм**
(усі речення однакової довжини, лікується реченням на три слова поруч із реченням на тридцять).

**Як фіксити.** Викинута конструкція замінюється **спостереженням із числом**: «З 60 акаунтів,
які ми онбордили, залишились тільки ті, хто заходив чотири рази за перший тиждень.» Нема числа
чи факту → речення видаляється цілком. Переформулювання в іншу риторику повертає те саме.

Ялинкові булети з перевірки на тріаду виключені: коротка паралельна форма там вимога формату.

Прогін краще автоматизувати. Скіл `anticopywriting-ai` має детектор, який повертає
`verdict: pass|fail` і список `hard_fails` саме по цих конструкціях:

```bash
python3 <шлях-до-скіла>/anticopywriting-ai/scripts/detect.py draft.md --lang uk --mode post --pretty
```

Що передгейт НЕ ловить і лишається судді: якість хука, м'ясо, вигадані цифри, структура
фреймворку, збіг із воронкою.

## Hard fails (авто-reject, гейт не береться незалежно від суми)

- Порушення «ЩО НІКОЛИ НЕ ПИШЕМО» (стратегія Секція 6 Voice).
  - **Виняток:** «не X, а Y» / дзеркальний антитезис — НЕ hard fail. У **хуку** (1-й рядок / трейлер) = дозволено, це панч. Поза хуком = soft minus у категорії 5, не reject.
- Вигадана цифра / факт не з патронів (§3.4 стратегії).
- CTA у формі питання («а у вас як?», «на якому кроці у вас діра?»). Фінал = директив:
  команда, коментар-гейт або «напишіть в особисті». Правило посилене 2026-08-12.
- Emoji або хештег у першому рядку.
- Будь-яка конструкція зі структурного передгейта (розділ вище).

**Коментар-гейт («напишіть "GTM" в коментарі») hard fail-ом НЕ Є** (рішення Віктора
06.08.2026). Раніше стояв тут як engagement bait; знято по факту: KIT-пост на цьому ж
механізмі зібрав 399 коментарів і 11k показів, шедоубан не справдився.

Hard fail → повернути з поміткою `HARD_FAIL: <що>`, у loop це найвищий пріоритет фіксу.

## Протокол сліпого судді

**Дефолт = субагент (Task), чистий контекст.** НЕ той самий виклик, що писав пост — інакше
модель пам'ятає чому обрала хук/референс і завищує собі оцінку (той самий «письменник ставить
оцінку сам собі», що гейт і ловить). Кожен rescore у loop = новий субагент, не «докрути попередню».

Суддя отримує ТІЛЬКИ:
1. Текст драфту.
2. Тип поста + формат (для вибору структурних критеріїв 3–4).
3. Список «ЩО НІКОЛИ НЕ ПИШЕМО» + signature-патерни автора (для категорії 5).
4. Цю рубрику.

Суддя НЕ отримує: чому обрали ідею, outlier-референс, hook draft з картки, попередні ітерації,
похвалу/контекст «ми старались». Судить холодно текст як читач у фіді.

Вихід судді (JSON):
```json
{
  "scores": {"hook":0,"trailer":0,"meat":0,"structure":0,"voice":0,"format":0,"cta":0},
  "total": 0,
  "hard_fails": [],
  "lowest": "<категорія>",
  "one_fix": "<один конкретний хід для найслабшої категорії>"
}
```

## Loop-until-gate

**Гейт за замовч. = структурний передгейт чистий І 90/100 І 0 hard_fails судді.** (Charlie тримає 95; 90 реалістичніше для UA-драфту з voice-обмеженнями — переможе калібрування, а не магічне число.)

0. Пройти структурний передгейт. Спрацювало → фіксимо і перевіряємо ще раз.
   Суддю спавнимо лише на чистому драфті.
1. Суддя грейдить драфт → score.
2. Якщо `hard_fails` не порожні → фіксимо їх першими.
3. Інакше фіксимо `lowest` категорію (застосувати `one_fix`).
4. Rescore СЛІПО (свіжий виклик, не «докрути попередню оцінку»).
5. Повтор поки передгейт чистий І `total ≥ 90 && hard_fails == []`.
6. **Стоп після 3 ітерацій** без взяття гейта → показати користувачу з поміткою «gate не взято, найслабше = X», рішення за людиною. Мовчазний авто-шип нижче гейта — заборонено.

## Калібрування рубрики з даних (winner-vs-flop, крок Charlie 1–2)

Рубрика не статична — раз на квартал звіряємо з реальністю (джерело: Posts DB через
`linkedin-tracking` + переможці з `07-repurpose`):

1. Взяти топ-N winners (gem/strong) і bottom-N flops за §6.3 (залучення **І** потік лідів, не лише лайки).
2. Прогнати обидві групи через сліпого суддю по цій рубриці.
3. **Перевірка валідності:** winners мають набирати помітно вище flops. Якщо ні — рубрика міряє не те.
4. Знайти, що РЕАЛЬНО відрізняє winners від flops у автора → підняти вагу тієї категорії / додати
   author-specific критерій. Приклад Viktor: personal/vulnerability б'є теорію → у категорії 3
   «унікальний фід» цінувати особисту ставку вище за generic-експертизу.
5. Перекалібрувати гейт-поріг, якщо 90 систематично ріже winners або пропускає flops.

Це і є Charlie-місток: `winners/flops (07 + tracking) → рубрика → грейдер`. Той самий вхід, що
07-repurpose використовує для рециркуляції, тут будує критерій якості.
