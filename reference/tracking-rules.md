# Правила трекінгу (для 09-track)

Нормативка вимірювання: звідки беруться числа, як рахується резонанс, коли пост стає
переможцем і як спостереження перетворюється на вагу в рекомендаторі. Читати ПЕРЕД
будь-яким режимом `09-track`.

Головне правило зверху (methodology §6.3): контент оцінюється **двома осями — резонанс І
потік діалогів**. Тема, що дає діалоги з ICP, цінніша за тему, що дає охоплення від колег.

---

## 1. Джерела даних і межі кожного

| Джерело | Що дає | Межа (не обходиться) |
|---|---|---|
| **AggregateAnalytics XLSX** (профіль → Analytics → Export) | покази (охоплення) + взаємодії | **тільки топ-50 за вікно експорту**; пости поза топ-50 показів не мають взагалі. Один файл на квартал, інакше рік не покритий |
| **Shares.csv** (LinkedIn data export) | повний текст, дата, URL кожного поста | приходить листом за ~24 год |
| **Rich_Media.csv** (той самий експорт) | формат поста (склейка за часом) | без нього формат = ручне поле |
| Локальні чернетки `.md` | кут, рубрика, теми, тип, воронка | ручна класифікація |
| **Діалоги / ліди / дзвінки** | головний сигнал якості | ручний ввід або CRM; автоматично нізвідки не береться |

**Покази — author-only.** Жоден API, скрапер чи Apify-актор їх не віддає. Пропонувати
«витягнути покази автоматично» = помилка, а не оптимізація.

## 2. Склейка

Ключ поста — **share id** з URL (`share-<id>` або `ugcPost-<id>`). Інжест робить
`build_archive.py`: зливає джерела в `archive/posts.jsonl`, ручні поля (кут, рубрика, теми,
формат, воронка) переживають перебудову. Пост, що потрапив у два експорти, лишає **більше**
значення — покази накопичуються, не скидаються.

## 3. Бейзлайн автора — ковзний, не загальний

Усі порівняння — проти **власної медіани**, ніколи проти чужих абсолютів (500 лайків = шкала
US-інфлюенсера, не B2B-фаундера).

База рахується **на момент публікації кожного поста**: медіана **12 постів, опублікованих
ДО нього** (окремо охоплення, окремо ER). Не одна медіана на весь архів.

Чому саме так — перевірено на архіві з 214 постів за 19 місяців: охоплення акаунта за цей час
впало десятикратно (медіана 2025 року — десятки тисяч, медіана останніх місяців — ~1.5 тис).
Одна загальна медіана віднесла **65% постів у переможці**, бо міряла старі пости лінійкою
нових. Ковзний бейзлайн дав робочий розподіл: 26% ≥ 1.5, 66% у нормі, 8% слабких.

Побічний плюс: RI поста **не змінюється заднім числом**, коли акаунт росте або падає. Пост
міряється своєю епохою.

- Менше 6 попередніх постів із даними → бейзлайн ненадійний: показувати сирі числа, тіри не ставити.
- **Самоперевірка:** медіана RI по всьому архіву має вийти ≈ 1.0. Вийшло помітно більше або
  менше — бейзлайн порахований неправильно (майже завжди це загальна медіана замість ковзної).

## 4. Індекс резонансу (RI)

```
ER    = (лайки + коменти + репости) / покази
RI    = 0.6 × (покази / медіана_показів_12_попередніх)
      + 0.4 × (ER     / медіана_ER_12_попередніх)
```

- Показів нема (пост поза топ-50) → RI рахується **тільки з осі ER**, запис несе прапорець
  `[немає показів]`. Домальовувати охоплення заборонено.
- Нема ні показів, ні взаємодій → `RI = null`, пост у бейзлайн не входить.

## 5. Дві осі → квадранти

Друга вісь — **діалоги** (розпочаті розмови, не лайки).

| Квадрант | Умова | Що це означає | Що робити |
|---|---|---|---|
| 💎 **Самородок** | RI ≥ 1.5 і діалоги ≥ 1 | зайшло і привело людей | у рециркуляцію першим, лід-магніт-кандидат |
| 📣 **Охоплення без заявок** | RI ≥ 1.5, діалоги = 0 | резонанс у колег, не в ICP | переписати кут під ICP, не множити формат |
| 🎯 **Тихий лідоген** | RI < 1.5, діалоги ≥ 1 | мало охоплення, але купують | **найцінніше для переробки** — той самий меседж у сильнішому форматі |
| ⚪ **Слабкий** | RI < 0.7 і діалоги = 0 | не спрацювало | у бейзлайн, у рециркуляцію не йде |

Між 0.7 і 1.5 без діалогів — `baseline`, робоча норма, не привід щось міняти.

**0 ≠ порожньо.** Діалоги невідомі (не питали / не заповнено) → це `null`, а не нуль:
квадрант не ставиться, пост тірується по RI з прапорцем `[діалоги невідомі]`.

## 6. Тір у Posts DB

| Tier | Умова |
|---|---|
| `gem` | RI ≥ 1.5 **і** діалоги ≥ 1 |
| `strong` | сильна рівно одна вісь (RI ≥ 1.5 або діалоги ≥ 1) |
| `baseline` | RI 0.7–1.5, діалоги 0 |
| `weak` | RI < 0.7, діалоги 0 |

**Право на рециркуляцію** (`Recycle eligible`) = tier ≥ `strong` І вік поста:
конверсія формату — від **45–60 днів**, републіш того ж формату — від **90 днів**
(methodology §2.6, §4 п.11). Молодший пост переможцем лишається, у пул не йде.

## 7. Гейти чесності

1. **Покриття** — у кожному звіті рядок «показів по N з M постів (X%)». Без нього читач
   думає, що бачить усі пости, а бачить топ-50.
2. **Вікно вимірювання** — фіксувати дату експорту в записі. Покази ростуть; порівнювати
   пост, виміряний на 3-й день, з постом на 30-й — помилка.
3. **Контрольні точки** — дивитись день 3 / 7 / 10, не лише перші 48 год (§4 п.11).
4. **Не вигадувати** — порожнє поле лишається порожнім і в звіті пишеться «немає даних».

## 8. Калібрування (місячний режим)

Розрізи, по яких рахується медіанний RI сегмента проти загальної медіани: **пілар · формат ·
кут (viral lever) · тип хука · довжина · день тижня**.

```
вага_сегмента = clamp(медіана_RI_сегмента / загальна_медіана, 0.6, 1.4)
```

**n-гейт** (скільки постів у сегменті):

| n | Що робимо |
|---|---|
| ≥ 4 | пишемо вагу в Секцію 7 стратегії — рекомендатор її враховує |
| 2–3 | пишемо як «сигнал, не висновок», вага не змінюється |
| ≤ 1 | не пишемо нічого |

Куди йде результат:
- **Секція 7 стратегії клієнта** (Notion) — таблиця відкаліброваних важелів з `n` і датою.
  Це те, що читає `04-weekly-plan` на кроці скору.
- **`07-repurpose`** — `angle_weight` матриці й `validated_factor` беруться звідси, а не
  з дефолтів.
- **`grader-rubric.md`** — переможці й провали як приклади для калібрування сліпого судді.

Дефолтна таблиця важелів у `methodology.md` §5 **не переписується**: вона — стартова гіпотеза
для нового клієнта. Калібрування живе в стратегії конкретного клієнта.

## 9. Чого не робимо

- Не тягнемо покази з API чи скраперів — їх там нема.
- Не ставимо тір по лайках у відриві від бейзлайну автора.
- Не рахуємо охоплення успіхом: 📣 без діалогів — це діагноз, а не перемога.
- Не міняємо ваги на вибірці з 1–3 постів.
- Не перезаписуємо ручну класифікацію (кут, рубрика, теми) автоматичним інжестом.
